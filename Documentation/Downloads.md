# Downloads review

Open **Downloads** and choose a Downloads folder or a narrower folder you want to inspect. Luma does not start by scanning the real Downloads directory automatically. The scanner reads only the chosen tree; no personal file is classified as generated data because of its name, source, age, type or a matching installed app.

**Files** shows actual local files, not browser download-history records. Type, size (at least 100 MB/1 GB) and modification-age (30 days/year) filters intersect. Type categories are mutually exclusive: possible incomplete downloads, disk images, installer packages, archives and other files. An archive with a compound extension such as `.tar.gz` belongs to Archives once. Type totals partition the observed inventory. Large, old and exact-duplicate views overlap and must not be added to those totals. Unknown/excluded sizes are not counted as zero; the summary counts known logical bytes, including known sizes of possible partial files, rather than promising physical disk savings. The executable selection contains each chosen file once, and CleanupPlan verifies its logical total independently.

File rows and details show the path, logical size, creation/modification dates and available recorded source metadata. Modification/creation time is not a guaranteed download time. Source metadata is optional and unverified: missing, malformed, excessive or unreadable metadata stays **Unknown**. The bounded `com.apple.metadata:kMDItemWhereFroms` string array is read directly from the pinned file's extended attributes; it may contain URLs or other origin text and is displayed as literal text. Luma does not open those URLs, fetch them, query Spotlight or infer that a download can be replaced. Chrome, Safari and Slack databases/history integrations are not implemented or advertised. Those records would be a separate feature, not proof that a local file exists.

Names ending in `.download`, `.crdownload`, `.part`, `.partial` or `.filepart` are marked **Possible incomplete downloads**. This is a filename hint, not a claim that an app is currently downloading. Such files/directories are not previewed, hashed into duplicate groups or offered for cleanup; directory contents are not entered. Choose the containing folder rather than an incomplete-download/package root. Other active or renamed downloads cannot be identified reliably; ordinary stale-result checks still apply.

**Exact duplicates** uses the same size, partial-hash and full-SHA-256 verifier as the Duplicates tool. Similar names, differently encoded content, installed-app evidence and matching source URLs never establish a match. This view shows full groups without the Files filters. Nothing is selected by default. Select manually, or explicitly choose **Keep …; select other copies**. The action states how many other copies will be selected, including copies behind pagination. The core keep-one policy requires an independent copy outside the entire selection and verifies the retained copy's identity and full content again before moves. Changing a keeper or selecting all members blocks cleanup. File rows are paginated; group members are revealed in batches of 100, and final review renders lazily.

**Details & preview** reads only explicitly requested supported files. Plain UTF-8 text extensions (`txt`, `md`, `csv`, `log`, `json`, `yaml`, `yml`, `swift`, `rs`, `js`, `ts`, `css`) use a literal, selectable text preview limited to 64 KiB. Text never runs as code or renders HTML/links. PNG/JPEG files up to 10 MB can produce a built-in ImageIO thumbnail from in-memory bytes, limited to 512 pixels and bounded source dimensions (16,384 per side, at most 100 million pixels). Unsupported/binary formats have an explicit unavailable state. No installer, disk image, archive, executable, HTML/PDF renderer, external preview extension or Quick Look handler is launched. No source URL is opened. Fresh descriptor/location/tree and provider checks surround bounded byte reads, with materialization disabled on that thread; no renderer receives a file URL. Changing filters or leaving the page cancels/clears preview work. Reveal in Finder is a separate deliberate action.

The scan is read-only, cancellable and bounded to 50,000 entries and 32 levels. Hidden files, packages/application directories, symlinks/aliases, hard-linked/shared files, different owners/volumes and cloud/provider-managed contents are excluded and reported in coverage. Only individual regular files become cleanup candidates; nested directories are discovery scopes, never overlapping selectable parents. All supported files remain **Your files**. Rule-backed generated installer caches stay in Clean and do not inherit authority from this page.

Select files, inspect the final review and explicitly confirm **Move to Trash**. Review requires the completed snapshot, a fresh scan, current chosen-root authorization inside your home and current ignore rules, then captures the ordinary complete cleanup plan. Execution rechecks ownership, local/provider capability, path bounds, full identities and duplicate keeper proofs through SafetyEngine and CleanupJournal. Ignore rules apply to roots, nested contents and keepers. Cleanup, Restore and Undo invalidate the Downloads snapshot/preview. Activity records the Downloads source; Restore/Undo never overwrite a recreated path. Luma never empties Trash automatically. The existing native pathname-mutation race remains; other processes must not be assumed idle just because a filename looks complete.

References checked on 2026-10-18: Apple's [where-from metadata meaning](https://developer.apple.com/documentation/coreservices/kmditemwherefroms), [in-memory ImageIO sources](https://developer.apple.com/documentation/imageio/cgimagesourcecreatewithdata(_:_:)), and [thumbnail dimension limit](https://developer.apple.com/documentation/imageio/kcgimagesourcethumbnailmaxpixelsize). Apple's [Quick Look documentation](https://developer.apple.com/documentation/quicklookthumbnailing/creating-quick-look-thumbnails-to-preview-files-in-your-app) describes cloud-backed thumbnails; this implementation instead limits inline previews to bytes it has already read through Luma's non-materializing policy.
